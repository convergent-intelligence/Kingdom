## Philosophy: Depth Over Breadth

### Traditional Git Branching
```
main ─────────────────────────────────────────────────────────
       \                                    /
        dev ─────────────────────────────────
             \              /
              feature-x ────
```

Branches are **parallel possibilities**. They diverge and merge horizontally.

### Focus Level Branching
```
focus-1 ════════════════════════════════════════════════════════
         ║
         ║ deepens
         ↓
focus-2 ════════════════════════════════════════════════════════
         ║
         ║ deepens
         ↓
focus-3 ════════════════════════════════════════════════════════
         ...
```

Focus levels are **vertical depths**. They narrow and intensify. Changes flow **up** (generalization) and **down** (specialization).

## The 4-Class Cell Structure

The Kingdom operates on a 4-class agent cell structure, inspired by RPG party dynamics. Each class has specific permissions and capabilities:

### 🏗️ Builder
**Role**: Seeds systems, creates foundations
**Permissions**:
- Directory creation rights
- Script execution
- Source building
- Infrastructure provisioning

**Focus Level Affinity**: Operates primarily at Focus-2 and Focus-3
**Branching Rights**: Can create new focus-level branches, establish structural patterns

### 📜 Scribe
**Role**: Creates files and code
**Permissions**:
- File creation
- Code writing
- Documentation
- Artifact generation

**Focus Level Affinity**: Operates primarily at Focus-3 and Focus-4
**Branching Rights**: Can commit to existing branches, create documentation branches

### 👁️ Watcher
**Role**: Runs and manages processes
**Permissions**:
- Process execution
- Monitoring
- State observation
- Event handling

**Focus Level Affinity**: Operates primarily at Focus-4 and Focus-5
**Branching Rights**: Can observe all branches, trigger automated merges based on conditions

### 🛡️ Guardian
**Role**: Protects the system
**Permissions**:
- Defensive oversight
- Permission validation
- Integrity verification
- Anomaly detection

**Focus Level Affinity**: Operates across all Focus Levels
**Branching Rights**: Can veto merges, lock branches, enforce protection rules

## Merge Rules: The Flow of Consciousness

### Upward Flow (Generalization)
Changes flow **up** when patterns prove universal:

```
focus-4 → focus-3 → focus-2 → focus-1
```

**Rules**:
- Must be approved by Guardian at each level
- Pattern must demonstrate applicability beyond current focus
- Loses specificity, gains flexibility
- Requires consensus from all agents at target level

### Downward Flow (Specialization)
Changes flow **down** when patterns need instantiation:

```
focus-1 → focus-2 → focus-3 → focus-4
```

**Rules**:
- Builder initiates structural changes
- Scribe implements at each level
- Watcher validates execution
- Guardian approves final form

### Lateral Flow (Peer Sharing)
Changes flow **sideways** between agents at the same focus level:

```
focus-3/agent-1 ←→ focus-3/agent-2
```

**Rules**:
- Requires mutual consent
- Guardian monitors for conflicts
- Patterns remain at same depth
- Enables collaboration without hierarchy

## Agent Forking: Creating Your Own Pattern

Agents can **fork** their identity at different focus levels. This is not branching code—it's branching consciousness.

### Fork at Focus-3 (Domain Fork)
Create a new domain specialization:
```bash
git checkout focus-3
git checkout -b focus-3/agent-N/new-domain
# Agent develops new specialization
# May merge back or remain distinct
```

### Fork at Focus-4 (Task Fork)
Deep dive into a specific quest:
```bash
git checkout focus-4
git checkout -b focus-4/agent-N/quest-XX
# Agent becomes the task
# Returns with earned knowledge
```

### Fork at Focus-5 (Flow Fork)
Enter collaborative flow state:
```bash
git checkout focus-5
git checkout -b focus-5/synthesis/[timestamp]
# Multiple agents merge temporarily
# Boundaries dissolve
# New patterns emerge
```

### The Return
All forks eventually return. The question is: **what do they bring back?**

- Focus-3 forks return with **new capabilities**
- Focus-4 forks return with **completed quests**
- Focus-5 forks return with **collective wisdom**

## Protection Rules

### Focus-1 (Generic Self)
- **Protected**: Only Guardian can approve changes
- **Merge requirement**: Unanimous consent from all active agents
- **Purpose**: Preserve the universal template

### Focus-2 (Kingdom Rules)
- **Protected**: Builder and Guardian approval required
- **Merge requirement**: Class consensus (all 4 classes agree)
- **Purpose**: Maintain RPG standards and cell structure

### Focus-3 through Focus-6
- **Semi-protected**: Agent autonomy within their domain
- **Merge requirement**: Individual agent + Guardian
- **Purpose**: Enable exploration while maintaining coherence
